# 功能数据导入

使用纯脚本实现二开数据导入/验证，而无需进行Java二开

功能位置：Marmot工作台→Hub→功能数据导入

**注意：API请求路由优先使用业务功能服务，只有纯配置表的界面可用sada，禁用hmde**

开发过程如下

**1、新建导入模板**

需要使用模板编码

模板编码有两种来源

&#x20; 1）老导入使用【导入模板管理】中的模板编码

&#x20; 2）新导入使用【组合业务对象】→【导入模板】中的模板编码

上传的文件会根据模板中维护的信息来进行字段对应

**2、确定脚本类型**

根据实际需求确定需要使用的脚本，本功能提供了批量导入的方式和四种验证方式

![](../../_helper/images/image_0OJ-IGE_Jo.png)

导入方式说明：

批量导入：调用脚本时会传入所有EXCEL中的数据，且会在“数据导入”的动作执行时执行脚本

&#x20;

![](../../_helper/images/image_KuU2n3vOnK.png)

四种验证方式说明：

新增验证（逐条）：在校验过程中新增一条校验，且EXCEL中的每一条数据都会单独调用一次脚本。

新增验证（批量）：在校验过程中新增一条校验，调用脚本时会传入所有EXCEL中的数据。

替换验证（逐条）：替换已存在的所有校验规则，且EXCEL中的每一条数据都会单独调用一次脚本。

替换验证（批量）：替换已存在的所有校验规则，调用脚本时会传入所有EXCEL中的数据。


例:
现在有一个已存在的模板编码 且你在java里已经写了一个校验器
新增:在这个校验器后再执行一个js写的校验器
替换:直接覆盖java里的校验器

注：验证仅会在数据验证时触发

根据实际需求，可能会出现需要单独增加验证规则的场景，只需要在此功能下维护好需要增加验证的对应模板编码，并新增一条验证规则即可，无需添加导入脚本。

部分场景下即可无需在JAVA标准代码中添加埋点便实现二开。

特殊场景:
当一个导入编码在标准中为批量校验时,在脚本中设置逐条检验是无效的
反之,若导入编码在标准代码中为逐条校验时,在脚本中设置逐条/批量均有效

**3、参数说明：**

![](../../_helper/images/image_pxxxx0kDCn.png)

（需要填入对应的模板代码、租户、以及导入/验证脚本编码）

*   所属租户

&#x20;      即第一步中维护好的导入模板的编码，此项必输。

*   所属租户

    对应的租户，此项必输。

*   页签

    即导入模板中sheet页的页签，从0开始。页签会以sheetIndex的参数传入土拨鼠独立脚本代码中，便于在js代码中进行判断。意为同一个excel文件的多个页签的导入可以使用同一个土拨鼠独立脚本。    
   （默认0，可多选，最多到4，如有更多的需求请联系@王林青 添加）

*   验证方式&#x20;

    数据验证方式，可选新增批量验证、新增逐条验证、替换批量验证、替换逐条验证。非必输

*   验证代码&#x20;

    用于进行数据验证的土拨鼠脚本代码。非必输

*   导入方式

    会替换掉原有JAVA代码中对应导入编码下指定页签的导入代码。

    批量导入是一个数组，只会调用一次脚本。

*   导入代码

    用于导入的代码，这项操作和正常使用导入模板在java中写代码一致，最终需要调用objet.create进行数据导入。

**4、编写脚本：**

两种脚本编写方式说明：

两种方式中的input都是相同的，其中包含

&#x20; input.data:批量导入/验证时为数据，单独验证时为对象

&#x20; input.args:调用导入接口时路径上的参数

&#x20; input.info:

info中包含的信息如下：

`templateCode` 模板编码 如: input.info.templateCode

`tenantNum` 租户编码

`sheetIndex` 页签


为了方便可以解构成以下形式
```javascript
function process({ data, info = {}, info:{templateCode,tenantNum,sheetIndex}, args = {} }) {
    STD.Logger.info("data: {}",data);
    STD.Logger.info("info: {}",info);
    STD.Logger.info("args: {}",args);

    STD.Logger.info("templateCode: {}",templateCode);
    STD.Logger.info("tenantNum: {}",tenantNum);
    STD.Logger.info("sheetIndex: {}",sheetIndex);

}
```


1、校验脚本

校验的脚本和java中思想一致，只需要在通过校验时返回

```javascript
return {"result":"true"}
```

即可校验为返回成功

遇到校验不通过的数据时，也可以直接抛出错误以直接显示在页面

```javascript
 throw new STD.SimpleException('xxxxxxxxx');
```

关于校验数据时的报错信息
分为两种情况
### 逐条校验
在逐条校验的情况下,只需验证错误后将错误抛出即可显示到每条数据对应的行上,以及 return {"result":"false"} 

### 批量校验
在批量校验的情况下,由于js代码只运行一次,所以中途如果遇到数据不正确且想把对应错误数据显示到每一行上,则需要按照以下方案将对应错误信息按行返回,如:
```javascript
function process( input ){
    let errorMsg = {}
    let backInfo = {}
    input.data.forEach((x,index)=>{
        errorMsg[index] = x.templateCode+"---error---"+index
    })
    input.data.forEach((x,index)=>{
        backInfo[index] = x.templateCode+"---backInfo---"+index
    })
    //注意这里的result在有错误的情况下改成false,否则前台不会报错
    return { "result": false,
        "errorMsg":errorMsg,
        "backInfo":backInfo}
}
```


2、新增脚本

组装好数据后 将内容插入至对应的表即可。

```javascript
  let objectOperation = require("@M/v1/object");
  let create = objectOperation.create({object:"xxxxx",records:record});
```

注意：大批量的导入的事务很大，尤其是带有多语言的导入，所以注意下导入时进行分批，防止出现连接超时等情况。推荐使用 \_.chunk(数组,每一批的数量) 进行分批导入

```javascript
   //这是一个数组
   let arr = [1,23,4,5,6,7,8,9,09]
   //利用_.chunk的方式，将数组arr分为size为3的多个数组
   _.chunk(arr,3).forEach(onePage=>{
     STD.Logger.info("description: {}",onePage);
   })


```

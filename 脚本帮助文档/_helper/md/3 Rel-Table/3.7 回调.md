## 1、背景

配置表的使用越来越多，业务场景也越来越复杂，配置表的基础功能已经无法满足一些操作需求，因此对配置表的功能进行扩充，增加了配置表回调代码的配置。
配置表的回调代码解决了下面的问题：

- 无法动态控制字段的禁用/可录入
-  `Lov` 组件查询根据其他字段进行条件过滤
- 输入字段无法自定义验证校验逻辑
-  `Lov`  组件选中值后无法同时将  `Lov`  中的其他数据插入配置表对应字段
- 改变某个字段时不能自动的更改相关联的其他字段值
- 无法动态设置的默认值

## 2、使用

1、打开配置表定义。

![](../../_helper/images/rel-3.7.1.png)

2、单个字段定义时候可以动态对数据进行改变
暂时只支持  `disabled` 、 `validator` 、 `lovPara` 、 `bind`、`events`  这五个字段配置，其中前四个字段对应的都是一个回调方法。events比较特殊，他是一个object，暂时只支持两个key值：`create`，`update`

- bind: 绑定  `Lov`  选择字段
- lovPara:  `Lov`  查询条件处理
- disabled：禁用/可编辑处理
- validator：自定义校验
- events：事件

3、参数类型解释
`({ dataSet: DataSet, record: Record, name: String }) => TYPE: any`  
dataSet:  当前配置表的  `DataSet`  数据  
record: 当前配置表行的  `Record`  数据  
name: 当前字段名  
TYPE: 返回类型  
`events: {create: ({record, getCurrentUser})=>void,update: ({dataSet, record, name, value, oldValue, getCurrentUser})=>void,}`  
dataSet:  当前配置表的  `DataSet`  数据  
record: 当前配置表行的  `Record`  数据  
name: 当前字段名  
value：当前字段更新后的值  
oldValue：当前字段更新前的值  
getCurrentUser：方法获取当前账号信息  
## 3、例子

#### 1、disabled

```js
function getComputedProps() {
  return {
    disabled: ({ dataSet, record, name }) => !!record.get('nameHandle'),
  };
}
```
![](../../_helper/images/rel-3.7.2.png)

当  `nameHandle`  有数据的时候  `name`  置为 `disabled`
#### 2、lovPara


```js
function getComputedProps() {
  return {
    //lovPara: ({ dataSet, record, name }) => ({ xxx: record.get('xxx') }),
     lovPara: ({ dataSet, record, name }) => ({ enabledFlag: 1 }),
  };
}
```

![](../../_helper/images/rel-3.7.3.png)

在  `lovPara`  的条件中增加了  `enabledFlag:1` ， 所以  `Lov`   的查询条件中就带了这个查询条件
#### 3、bind


```js
function getComputedProps() {
  return {
    bind: ({ dataSet, record, name }) => 'groupIdLOV.groupName',
  };
}
```
![](../../_helper/images/rel-3.7.4.png)

⚠️ **注意**   `bind`  使用的时候要注意，此处的规范是，如果要绑定一个  `Lov` 内的字段数据， `bind`  返回的字符串的第一段为 字段编码+LOV, 例如上文中定义的是 `groupId`  为 `Lov`  选择框，下面的字段要获取  `groupName` ，就要返回一个 “groupIdLOV.groupName”，此处的 `LOV` 大写，为LOV获取字段标记。
#### 4、validator


```js
function getComputedProps() {
  return {
     validator: ({ dataSet, record, name }) => {
       return function() {
         return record.get("nameHandle") === '123' ? "输入为123，不允许输入该值" : true 
       }
     },
  };
}
```
![](../../_helper/images/rel-3.7.5.png)
⚠️ **注意**   `validator`  的返回必须为一个 `function` ， `function`  中可以进行一些校验判断，返回 `true`  为校验通过，返回字符串为校验不通过逻辑。
#### 5、events
events中的`create`，`update`中事件的触发条件不同：
- `create`是当打开新建 !12 （ 或编辑 ）! 时触发 !12 （  如何判断当前状态是编辑还是新建，可以通过当前配置表行的  `Record`  数据中是否有id这个字段值，没有则是新建状态。或者根据配置表中某些特殊的字段 ）!，你可以在不同的场景下给record set不同的默认值。`推荐`在配置表定义中定义字段时，当前字段的回调函数中events的create只处理当前字段。不推荐在一个字段中的回调函数中events的create处理该配置表的所有字段值；
- `update`则是更改某个字段的值时触发，多用于下拉框时，当更改下拉框A字段，B字段会根据A字段的内容自动的填充不同的值。可以用 update 来对A字段的值进行判断，给B set不同的值。`特别的` update 只处理当前回调函数所在的字段，不能将所有的字段的 update 事件都写在一个字段的回调函数中。

create和update中都支持获取到当前租户的信息，你可以使用`getCurrentUser()`得到想要的内容，还可以在events的两个事件中使用axios来请求数据， 如：```axios.post('',{}).then((res)=>{})```


```js
events: {
  create: ({ record, getCurrentUser }) => {
    // 可以通过record.get('id')来判断是否是新建或者其他方式
    if(record && !record.get('id')){
      const user = getCurrentUser() || {};
      record.set('createdUserName', user.realName)
	  // record.set('字段名', 字段值)
    }
  },
  update: ({ dataSet, record, name, value, oldValue, getCurrentUser }) => {
  if(value === '某个值'){
    // 可以根据当前字段的值来更改其他字段值
    record.set('其他字段名', 你想更改的值)
    }
  },
}
```

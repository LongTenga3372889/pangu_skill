# 异常处理 & 错误通知
>如何处理MarmotScript的异常  
>   
> MarmotScript的异常处理在JavaScript的基础上，有一定的扩展

***

## throw & catch
**脚本端处理：**

JavaScript是不具备强类型能力的，故其throw与catch 的与其说是异常，不如说是对象
```javascript
try{
    throw {test:1}
}catch (e){
    //e 就是 {test:1}
}

//一般的JavaScript玩法
try{
    throw new Error('test');
}catch (e){
    //e 就是这个Error,通过 e.message取得错误信息
}

```
在MarmotScript中，为方便异常信息的翻译处理，我们提供了一种异常对象
```javascript
const {SimpleException,BusinessException}=require('@M/v1/exception');

throw new SimpleException('hpfm.yes');//自动进行 多语言/message翻译

throw new SimpleException("smodr.order.update.error","测试1","测试2");//返回消息支持占位符，多个占位符用逗号分隔

//如果Java中不处理，仍然想抛出页面可见异常，则进行如下操作
throw '错误信息';  //直接抛出字符串


//原本的BusinessExcpetion仍存在，但不再建议使用
```
**java端处理:**
```java
try{
    AdaptorHelper.executeAdaptorTask("SADA_CODE", "SRM-ZHENYUN", argMap);
}catch(TaskNotExistException | BusinessException e){
    //1.处理BusinessException
    if(e instanceof BusinessException){
        throw e.toCommonException();
        //或者throw new CommonException(e.getMessage());
    }
    //2.找不到埋点脚本不做处理最好
}
```

## 错误通知
MarmotScript引擎使用其生态的WebHook能力提供了错误通知功能
故在错误通知的背景下，异常分为了两种
> 无需关注的异常(不会进行错误通知)：SimpleException,BusinessException   
> 需要关注的异常(会错误通知):  其余都是

***

## 异常栈的查看

一个典型的MarmotScript异常信息如下
```text
[PROD] MarmotScript 报错通知
+ 埋点脚本点位编码 : 
SSRC_EVALUATE_SUMMARY_DETAIL_POST_HANDLE
+ 租户 : 
SRM-XXX 某公司
+ 异常信息 : 
TypeError: Cannot read property 'attributeBigint1' of undefined
+ TraceId : TZBzvQXT
+ 最后修改人 : xxx
+ 创建人 : xxx
+ 异常栈 : 
 <js>.process(line:33)  
 <js>.process(internal-script:1541)  
 <js>.:program(line:138)  
```

其中需要关注的主要内容如下注释

```text
[PROD] MarmotScript 报错通知
+ 埋点脚本点位编码 : 
SSRC_EVALUATE_SUMMARY_DETAIL_POST_HANDLE  //锁定脚本位置
+ 租户 : 
SRM-XXX 某公司
+ 异常信息 : 
TypeError: Cannot read property 'attributeBigint1' of undefined   //异常的信息
+ TraceId : TZBzvQXT // traceId
+ 最后修改人 : xxx
+ 创建人 : xxx
+ 异常栈 :   //异常栈，这里是重点
 <js>.process(guest:25)  //process函数，guest脚本，第25行
 <js>.:program(guest:91)  //process函数，guest脚本，第一行
 <js>.:program(script-ignite-frame:1)  //引擎启动层，无帮助
```

通过该注释，我们可以知道
```text
错误在脚本的第25行发生
错误信息，错误的traceId
错误发生的脚本名称，租户等信息
```

## T01 · catch 后只 log 不 throw / 空 catch

**严重度**：🔴 P0
**频次**：极高（grep `catch (e)` 在 100+ 脚本中匹配）
**真实证据**：

```javascript
// SITF_AGENCY_TASK_EXP_INVOKE-26.js:171-173 — catch 后只 log
} catch (e) {
  STD.Logger.error("信泰 agency messageExp dingtalk failed! {}", e.stack || e.toString());
  // ❌ 没有 throw，没有 push 到 outData，调用方完全不知道失败了
}

// HWFP_CARBON_COPY_READ.js:51-55 — catch 后 rethrow 但丢堆栈
try {
  receiver = BIZ.EmployeeHelper.getEmployee(STD.CurrentContext.getUserId()).employeeNum;
} catch (error) {
  throw "对应接收人不能为空";  // ❌ 丢原始堆栈
}
```

**危害**：
- 错误被吞掉 → 调用方看到 "SUCCESS"，但实际业务未完成 → 静默失败
- 数据不一致：MQ 消费者认为已处理，实际没处理 → 后续流程阻塞
- 排查困难：用户报问题，但日志没有任何错误

**推荐规避写法**：

```javascript
// ✅ 适配器脚本（外部调用）：保留在 catch 内，返回 ERROR 到 outData
} catch (e) {
  STD.Logger.error(logPre + " 失败：{}", e.stack || e.toString());
  outData.push({
    businessId: data.businessId,
    syncStatus: "ERROR",
    syncResponseMsg: e.toString()
  });
}

// ✅ 业务脚本（校验/审批）：rethrow 时保留堆栈
try {
  riskyOperation();
} catch (e) {
  STD.Logger.error(logPre + " 异常：{}", e.stack || e.toString());
  throw new STD.SimpleException("hpfm.error.business", e);  // 保留 cause
}
```

## T02 · 未判空直接 `.xxx` 链式调用

**严重度**：🔴 P0
**频次**：高（精读 14 个脚本 100% 出现）
**真实证据**：

```javascript
// SSLM_LIFE_CYCLE_STAGE_CHANGE_APPROVR_AFTER-3.js:32-38 — 拼写错误的方法
let partner = objectOperation.quernOne({  // ❌ quernOne 应为 queryOne
  object: 'spfm_partner',
  condition: { ... }
});
if (partner && partner.supplierBasicId) {  // 即便有 null check， quernOne 也抛错
  supBasic = objectOperation.fetchById({...});
}

// SITF_AGENCY_TASK_EXP_INVOKE-26.js:191 — 解引用
return userIdresult.result.userid  // ❌ userIdresult.result 可能 undefined

// SITF_RCV_ASYNC_EXP.js:115 — 字符串字面量拼接
let link = itfCtx.pcUrl + itfCtx.serviceUrl + agencyExp.pcUrl;  // ❌ undefined 拼接
```

**危害**：
- 抛 NPE / TypeError → 整个 process 崩溃 → 整批失败
- 即便有 try/catch 兜底，错误信息对用户无意义

**推荐规避写法**：

```javascript
// ✅ 链式访问用 optional chaining
let link = `${itfCtx.pcUrl ?? ""}${itfCtx.serviceUrl ?? ""}${agencyExp.pcUrl ?? ""}`;

// ✅ 返回值解引用前 null check
let result = userIdresult?.result;
if (!result || !result.userid) {
  throw "钉钉 userId 查询失败：" + JSON.stringify(userIdresult);
}
return result.userid;

// ✅ array 边界检查
let arr = response.Result?.ResponseStatus?.SuccessEntitys || [];
let first = arr[0];
let num = first?.Number || "";

// ✅ 字典式默认值兜底
let supplierOther = objectOperation.queryOne({...}) || {};
let engName = supplierOther.attributeVarchar1 || "";  // 即使 supplierOther 为空也不会崩
```

## T04 · v2 ORM 漏 tenantId → 跨租户数据泄漏

**严重度**：🔴 P0（数据安全级别）
**频次**：中（v2 ORM 使用中较常见）
**真实证据**：

```javascript
// SSRC_RFX_CHECK_PRICE_SUBMIT_VALIDATE-5.js:12, 19 — v2 ORM 无 tenantId
let itemInfo = STD.Database.table("smdm_item").selectOne({itemCode: lineItem.itemCode});
// ❌ 没传 tenantId → 可能查到其他租户的物料
let category = STD.Database.table("smdm_item_category").selectOne({categoryId: lineItem.itemCategoryId});

// SITF_PO_EXP_INVOKE-1.js:331-334 — v2 ORM 也漏 tenantId
term = queryOne("smdm_payment_term", {
  termId: inData.termsId
  // ❌ 缺 tenantId
});
```

**危害**：
- **数据安全**：跨租户读数据 → 隐私/合规问题（P0）
- 性能：全表扫描无 tenantId 过滤

**推荐规避写法**：

```javascript
// ✅ v2 ORM 必须手动加 tenantId
let itemInfo = STD.Database.table("smdm_item").selectOne({
  itemCode: lineItem.itemCode,
  tenantId: tenantId   // ✅ 强制加
});

// ✅ 用 helper 函数自动注入（SSRC_RFX_HEADER_QUERY_AFTER_HANDLE.js:171-189 模板）
function queryOne(object, condition) {
  if (condition.tenantId == null) {
    condition.tenantId = organizationId;
  }
  return objectOperation.queryOne({object, condition});
}

// ✅ 更优：升级到 v3 ORM（自动处理 tenantId）
let itemInfo = objectOperation.queryOne({object: "smdm_item", condition: {itemCode: lineItem.itemCode}});
```

## T05 · lodash/moment 全局假设未 require

**严重度**：🟡 P1
**频次**：高（精读 14 个脚本 100% 使用 lodash 但仅 50% require）
**真实证据**：

```javascript
// SITF_PO_EXP_INVOKE-1.js — 顶部无 require('lodash')
// 但代码内 100+ 处使用 _.isEmpty / _.find / _.map / _.keys / _.sortBy / _.distinct
let invInventoryCode = _.isEmpty(poLine.poLocExpList) ? null : poLine.poLocExpList[0].invInventoryCode;

// SPUC_PR_QUERY_PERMISSION-2.js — 顶部 require("@M/v1/logger") 但 lodash 也没 require
// ❌ 如果 v3 引擎不注入 lodash 全局，这里会 ReferenceError
```

**危害**：
- v3 引擎（GraalVM）的 polyglot 环境**默认注入 lodash 全局**，但**不保证跨所有客户**
- 客户二开脚本如果引入到非标准环境（开发/测试）→ ReferenceError

**推荐规避写法**：

```javascript
// ✅ 显式 require
const _ = require("lodash");
const moment = require("moment");

// ✅ 或在 process 入口判断
if (typeof _ === "undefined") {
  throw "脚本依赖 lodash，请联系平台";
}
```

## T06 · JSON.parse vs STD.SAFE_JSON.parse 混用

**严重度**：🟡 P1
**频次**：高（grep 显示 100+ 用 JSON.parse，100+ 用 SAFE_JSON）
**真实证据**：

```javascript
// SITF_GENERIC_POST_SCUX_COMMON8-1.js:9 — 不安全
if (typeof input.body == "string") {
  input.body = JSON.parse(input.body);  // ❌ 外部传入可能含 NaN/null/未引号字段
}

// SITF_AGENCY_TASK_EXP_INVOKE-26.js:11 — 安全
let itfCtx = STD.SAFE_JSON.parse(STD.Constants.get("SITF_SINCETECH_BPM_CONFIG"));
// ✅ STD.SAFE_JSON.parse 是 v3 引擎扩展，安全处理各种边界
```

**危害**：
- `JSON.parse("undefined")` → SyntaxError
- `JSON.parse("{key: value}")` (key 不带引号) → SyntaxError
- 平台原生 SAFE_JSON.parse 兜底更好

**推荐规避写法**：

```javascript
// ✅ Bot 写脚本统一用 STD.SAFE_JSON.parse
let itfCtx = STD.SAFE_JSON.parse(STD.Constants.get("SITF_XXX_CONFIG"));
let response = STD.SAFE_JSON.parse(httpResponse);

// ✅ 唯一例外：JSON.stringify 可以继续用（无安全风险）
let body = JSON.stringify({key: value});  // 或 STD.SAFE_JSON.stringify 更安全
```

## T07 · 同名函数重复定义

**严重度**：🟡 P1
**频次**：中
**真实证据**：

```javascript
// SSRC_RFX_HEADER_QUERY_AFTER_HANDLE.js:266-275 vs 277-286
function page(object, condition, pageRequest) {  // 第一次定义
  if (condition.tenantId == null) condition.tenantId = organizationId;
  return objectOperation.page({...});
}

function page(object, condition, pageRequest) {  // ❌ 重复定义！后者覆盖前者
  if (condition.tenantId == null) condition.tenantId = organizationId;
  return objectOperation.page({...});
}
```

**危害**：
- JavaScript 函数声明（`function name()`）会被 hoisting，后者覆盖前者
- 看起来无害，但实际是历史修改没清理的痕迹 → 易引入 bug

**推荐规避写法**：

```javascript
// ✅ 每个函数只定义一次
// ✅ IDE / linter 配置 no-redeclare 规则
// ✅ 复制粘贴后立即删除旧版本
```

## T08 · HTTP 调用无超时控制

**严重度**：🟡 P1
**频次**：极高（90%+ 脚本）
**真实证据**：

```javascript
// SITF_AGENCY_TASK_EXP_INVOKE-26.js:108-113 — 无超时配置
let tokenInfo = STD.HttpClient.doGet(
  itfCtx.obtainAccessToken.replace("{appKey}", ...).replace("{appSecret}", ...),
  {}
);
// ❌ 如果钉钉 API hang，整个脚本卡死 → MQ 消费阻塞 → 积压

// SITF_RCV_ASYNC_EXP.js:566-577 — 同样无超时
let invokeRsp = STD.CodeBlock.execute("SITF_COMM_HTTP_TOOL", {
  systemName: ..., url: ..., method: 'post',
  httpHeaders: {...},
  bodyParam: requestBody
  // ❌ 没有 timeout 配置
});
```

**危害**：
- 外部系统 hang → 脚本 hang → MQ 消费阻塞 → 整个集群积压
- 网络抖动 → 失败重试 → 雪崩

**推荐规避写法**：

```javascript
// ✅ v3 引擎的 HttpClient 支持 timeout 参数（需确认）
let tokenInfo = STD.HttpClient.doGet(url, {}, null, {timeout: 5000});  // 5 秒

// ✅ 业务侧再包裹一层 try/catch + 重试
function httpWithRetry(url, options, maxRetry = 3) {
  for (let i = 0; i < maxRetry; i++) {
    try {
      let start = Date.now();
      let result = STD.HttpClient.doPost(url, options.headers, options.body, {timeout: 5000});
      if (Date.now() - start > 3000) {
        STD.Logger.warn("HTTP slow: " + (Date.now() - start) + "ms");
      }
      return result;
    } catch (e) {
      if (i === maxRetry - 1) throw e;
      STD.Logger.warn("retry " + (i + 1) + "/" + maxRetry);
    }
  }
}

// ✅ 熔断降级（更高级）
let circuitOpen = STD.Cache.get("circuit:xxx");
if (circuitOpen === "open") {
  throw "服务熔断中";
}
```

## T09 · 敏感凭据打到日志

**严重度**：🔴 P0（合规级别）
**频次**：中
**真实证据**：

```javascript
// SITF_AGENCY_TASK_EXP_INVOKE-26.js:69 — invokeRsp 含 token 字段
STD.Logger.info("SRM-SINCETECH|ADAPTOR|SITF_AGENCY_TASK_EXP_INVOKE invokeRsp: {}", invokeRsp);
// ❌ invokeRsp.OUTPUT 可能含 access_token / appSecret

// SITF_PO_EXP_INVOKE-1.js:454 — 请求体含 Basic Auth
info("requestJson1", { "INPUT": toString(requestJson) });
// ❌ Authorization header 已被拼成 'Basic xxx' 写入请求体
```

**危害**：
- **合规风险**：敏感凭据写入日志 → ELK / SLS 可被查 → 凭据泄漏
- 凭据泄漏 → 外部系统被攻击 → 数据泄漏

**推荐规避写法**：

```javascript
// ✅ 自定义 logger：自动脱敏
function info(key, obj) {
  let safe = sanitize(obj);
  STD.Logger.info(logPre + " " + key + " => " + STD.SAFE_JSON.stringify(safe));
}
function sanitize(o) {
  if (typeof o !== "object" || !o) return o;
  let clone = JSON.parse(JSON.stringify(o));
  ["Authorization", "Password", "AppSecret", "appSecret", "token", "access_token"].forEach(k => {
    if (clone[k]) clone[k] = "***";
  });
  return clone;
}

// ✅ 只打印长度/摘要，不打原始报文
STD.Logger.info("invokeRsp length: " + invokeRsp.length);
```

## T10 · 状态码硬编码 magic number

**严重度**：🟡 P1
**频次**：高
**真实证据**：

```javascript
// SITF_AGENCY_TASK_EXP_INVOKE-26.js:53
syncStatus: invokeRsp.code == 200 ? "SUCCESS" : "ERROR",
// ❌ 200 是 HTTP 状态码；业务 code 可能是 0/"0"/200

// SITF_RCV_ASYNC_EXP.js:799
let feedBackStatus = invokeRsp.code == 0 ? "SUCCESS" : "ERROR";
// ❌ 飞书 code 是 0；但 HTTP code 是 200

// SITF_HMSG_MESSAGE_EXP_INVOKE-3.js:141
syncStatus: 0 == status ? "SUCCESS" : "ERROR",
// ❌ 反向写法 0 == status（防 typo），但 magic number 仍是问题
```

**危害**：
- 不同外部系统 code 不同：SAP / 飞书 / 金蝶 / 钉钉 各有约定
- magic number 散落 → 维护噩梦

**推荐规避写法**：

```javascript
// ✅ 集中定义外部系统的成功判定
const ExternalSystem = {
  SAP: {successCode: 200, successField: "code"},
  FEISHU: {successCode: 0, successField: "code"},
  DINGTALK: {successCode: 0, successField: "errcode"},
  KINGDEE: {successCode: "1", successField: "operResult"}
};

function isSuccess(rsp, system) {
  let cfg = ExternalSystem[system];
  return rsp[cfg.successField] == cfg.successCode;
}

// 调用
let ok = isSuccess(invokeRsp, "FEISHU");
```

## T12 · GraalVM 假设（collectors/Java 语法）

**严重度**：🟡 P1
**频次**：中
**真实证据**：

```javascript
// SINV_RCV_TRX_DATA_SUBMIT_AFTER-5.js:38-42 — Java-style collectors
let pcHeaderGroup = queryList.collectors().groupingBy(x => x.fromPcHeaderId, x => x);
let pcHeaderMap = pcHeaderInfos.collectors().toMap(x => x.pcHeaderId, x => x, (a, b) => b);
let pcStageMap = pcStageInfos.filter(val => val.milestoneTime != null)
  .collectors().toMap(x => x.pcHeaderId, x => x, (a, b) => {
    if (moment(a.milestoneTime).isAfter(b.milestoneTime)) return a;
    return b;
  });

// SSRC_RFX_HEADER_QUERY_AFTER_HANDLE.js:241, 244, 708, 711 — 同样语法
return data.collectors().toMap(x => x[keyField], x => x);
```

**危害**：
- v3 引擎基于 GraalVM polyglot，**Java Stream API 部分暴露**
- 不是所有 v3 版本都支持（依赖 Marmot 引擎版本）
- 升级后可能突然失败

**推荐规避写法**：

```javascript
// ✅ 优先用纯 JS 替代
let pcHeaderGroup = {};
```

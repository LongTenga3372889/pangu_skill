## P01 · 脚本入口骨架

**适用场景**：所有脚本的固定头部结构。5284 个脚本均符合此骨架。

**代码模板**：
```javascript
/*
服务：<running_service>           // 如 srm-interface, srm-source
编码：<TASK_CODE>                  // 如 SITF_PO_EXP_INVOKE
描述：<一句话业务目的>
需求：cdp-XXXXXX【客户名】<场景>  // 引用 choerodon issue
*/
let objectOperation = require("@M/v1/object");   // 必引入 ORM
let tenantId = STD.CurrentContext.getExecutionTenantId(); // 或 getTenantId
// 其他 require...

function process(input) {
  STD.Logger.info("SRM-<客户简称>|ADAPTOR|<TASK_CODE> input: {}", input);
  // ... 业务逻辑 ...
  return input;  // 或 return { body, outData, _docInfoList }
}
```

**真实示例**：
- `SPUC_PR_QUERY_PERMISSION-2.js`（14 行，最简骨架）
- `SLOD_UPDATE_DATA_BY_CREATE-5.js`（144 行，中等骨架）
- `SITF_AGENCY_TASK_EXP_INVOKE-26.js`（192 行，复杂骨架）
- `SITF_PO_EXP_INVOKE-1.js`（713 行，超复杂骨架）

**注意事项**：
- 头部注释必须包含「服务/编码/描述」三要素（来自 scm `sada_adaptor_task_header` 元数据）
- `process(input)` 是 v3 引擎唯一合法入口函数；不能改名为别的
- 入口函数 `return input` 是 v3 主旋律（≈2500+ 个）；少数返回结构体

## P02 · v3 ORM CRUD 标准写法

**适用场景**：对象查/改/写。覆盖 ~98% 脚本。v3 引擎主推 API。

**代码模板**：
```javascript
const objectOperation = require("@M/v1/object");

// 1. 按主键查（无 lock）
let header = objectOperation.fetchById({object:"sodr_po_header", id: data.poHeaderId});

// 2. 条件单条
let one = objectOperation.queryOne({object:"hpfm_employee", condition:{employeeNum: data.assignee}});

// 3. 条件多条
let list = objectOperation.query({object:"sodr_po_line", condition:{poHeaderId: data.poHeaderId}});

// 4. 批量按主键查（id 数组）
let headerList = objectOperation.fetchById({object:"spcm_pc_header", id: _.keys(pcHeaderGroup)});

// 5. 局部更新（白名单字段）
objectOperation.updateOptional({
  object:"sodr_po_header",
  record: header,
  fields: ["attributeVarchar15", "attributeDecimal2"]
});

// 6. 整对象更新
objectOperation.update({object:"sodr_po_header", record: header});

// 7. 插入单条
objectOperation.create({object:"sodr_po_header", record: newHeader});

// 8. 批量插入（array of records）
objectOperation.create({object:"sodr_po_line", record: lineList});

// 9. 批量删除
objectOperation.remove({object:"sodr_po_line", id: [lineId1, lineId2]});

// 10. 分页查询（pageRequest）
let page = objectOperation.page({
  object:"sodr_po_header",
  condition:{tenantId, poTypeId},
  pageRequest:{page:1, size:20, sort:"creationDate,desc"}
});
```

**真实示例**：
- 单条 fetchById：`SSLM_LIFE_CYCLE_STAGE_CHANGE_APPROVR_AFTER-3.js:17-22`
- 条件多条 query：`SSRC_RFX_CHECK_PRICE_SUBMIT_VALIDATE-5.js:8` / `SITF_RCV_ASYNC_EXP.js:50-53`
- updateOptional 字段白名单：`SSLM_LIFE_CYCLE_STAGE_CHANGE_APPROVR_AFTER-3.js:73`
- 批量 create：`SPUC_SUBMIT_PO-8.js:71` / `SLOD_EXEC_AFTER_CREATE_DELIVERY.js:33`
- 分页 page：`SSRC_RFX_HEADER_QUERY_AFTER_HANDLE.js:266-275`

**注意事项**：
- ✅ 优先 v3 ORM（统一租户/审计/性能优化），新代码 100% 使用
- ⚠️ v3 ORM 必须传 `object` 参数（业务对象名 = 表名），无 `table()` 包装
- ⚠️ `updateOptional` 比 `update` 安全：fields 白名单避免覆盖审计字段
- ⚠️ `condition` 内嵌套对象须用 `{opr:"in", v:[...]}` 语法（见 P20）

## P03 · v2 ORM 兼容写法（STD.Database）

**适用场景**：老存量脚本（2022 年前发布）+ 部分批量操作（batchInsert/batchUpdateOptional 仍是 v2 优势）。

**代码模板**：
```javascript
const repository = STD.Database.table("sodr_po_line");

// 1. 按主键查
let line = repository.selectById(poLineId);

// 2. 条件单条
let line = repository.selectOne({poHeaderId, displayLineNum});

// 3. 条件多条
let lines = repository.select({poHeaderId, tenantId});

// 4. 批量按主键查
let list = repository.selectListById([id1, id2, id3]);

// 5. 局部更新（单字段）
repository.updateOptional(record, "attributeVarchar1");

// 6. 局部更新（多字段数组）
repository.updateOptional(record, ["attributeVarchar1", "attributeDecimal2"]);

// 7. 批量更新
repository.batchUpdateOptional(updateList, ["field1", "field2"]);

// 8. 批量插入
repository.batchInsert(insertList);

// 9. 批量删除
repository.batchDeleteByPrimary(deleteList);

// 10. 单条插入
repository.insert(record);
```

**真实示例**：
- v2 仍被大量使用：`grep "STD.Database.table"` 在 100+ 脚本中匹配
- `SSTA_CREATE_PAYMENT_BY_INVOICE_AFTER.js:35-36` 演示 batchUpdateOptional
- `SPUC_ORDER_BATCH_SUBMIT_HANDLE-2.js:27` 批量 updateOptional
- `SSRC_RFX_ADJUST_APPROVED_AFTER_HANDLE-4.js:81-85` 批量删除

**注意事项**：
- ⚠️ v2 ORM 新代码禁止使用（D2 统计显示存量 < 2%）；只在维护老脚本时使用
- ⚠️ v2 ORM 不自动注入 tenantId 过滤，必须手动加 `tenantId: tenantId`（很多脚本踩坑 → 见 T04）
- ⚠️ v2 与 v3 混用易破坏事务边界；优先统一为 v3

## P04 · 租户常量 + JSON 配置加载

**适用场景**：外部系统集成（>90% 接口脚本）。所有外部系统的 host/credentials/url 都在 `STD.Constants` 中。

**代码模板**：
```javascript
// 模式 A：标准命名 — 推荐
let itfCtx = STD.SAFE_JSON.parse(STD.Constants.get("SITF_<CUSTOMER>_<SYSTEM>_CONFIG"));
// 例：SITF_SINCETECH_BPM_CONFIG, SCUX_HLGF_RFX_OA_INFO

// 模式 B：别名 — 也常见
let itfCtx = JSON.parse(STD.Constants.get("SITF_<CUSTOMER>_<SYSTEM>_CONFIG"));

// 模式 C：取子模块
let oaConfig = STD.SAFE_JSON.parse(STD.Constants.get("SITF_XTHL_OA_CONFIN")).oa;
let erpConfig = STD.SAFE_JSON.parse(STD.Constants.get("SITF_DRYL_BPM_CONFIG")).erp;
let feishuCfg = STD.SAFE_JSON.parse(STD.Constants.get("BIGSAILING_FEISHU_OAPI_CONFIG"));

// 模式 D：BigInt 安全（外部返回大整数 id 时）
let itfCtx = JSONBig.parse(STD.Constants.get("SITF_LAXIAOYA_ITF_CONFIG"));

// 模式 E：CodeBlock 间接取（复杂场景）
let itfCtx = STD.CodeBlock.execute("SCUX_HLGF_FEISHU_UTIL", {
  functionCode: "Common.loadItfCtxFromConstant",
  ctxKey: "SITF_HLGF_FEISHU_OAPI_CONFIG"
});
```

**真实示例**：
- A 模式（SAFE_JSON）：`SITF_AGENCY_TASK_EXP_INVOKE-26.js:11-12`
- B 模式（JSON.parse）：`SSRC_RFX_HEADER_QUERY_AFTER_HANDLE.js:30`
- C 模式（子模块）：`SITF_SETTLE_INVOICE_EXP_INVOKE-6.js:3` 取 `kingDeeSystem`
- E 模式（CodeBlock）：`SITF_HMSG_MESSAGE_EXP_INVOKE-3.js:188-193`

**配置命名规范（约定俗成）**：
| 命名模式 | 含义 |
|---------|------|
| `SITF_<CUSTOMER>_<SYSTEM>_CONFIG` | SITF 系列集成配置（最常用） |
| `SCUX_<CUSTOMER>_<SYSTEM>_CFG` | SCUX 二开客户配置 |
| `SITF_<CUSTOMER>_<SYSTEM>_<SUB>_CFG` | 多个子系统时 |

**注意事项**：
- ⚠️ **必须使用 STD.SAFE_JSON.parse**（v3 引擎保证：不会因注释/未引号字段抛错），原生 `JSON.parse` 在 Bot 代码中扣分（不安全）
- ⚠️ Constants 配置中含敏感凭据（appSecret/appId/password）；日志打印时必须脱敏（见 T09）
- ⚠️ 配置可能为 null：`STD.SAFE_JSON.parse(STD.Constants.get("X") || "{}")`

## P05 · HTTP 调用 + Bearer Token 鉴权

**适用场景**：90% 集成脚本（SAP/金蝶/用友 NC/钉钉/飞书/泛微 OA）。

**代码模板**：
```javascript
// 1. 取 token
let tokenUrl = itfCtx.host + itfCtx.tokenUrl;
let token = STD.HttpClient.doGet(tokenUrl, null, null);
let tokenObj = STD.SAFE_JSON.parse(token);
// 校验
if (!tokenObj || !tokenObj.access_token) {
  throw "获取 TOKEN 失败：" + token;
}

// 2. 构造 header
let header = {
  Authorization: "Bearer " + tokenObj.access_token,
  "Content-Type": "application/json"
};

// 3. POST 调用
let url = itfCtx.host + itfCtx.apiUrl;
let invokeRsp = STD.HttpClient.doPost(url, header, requestData);
let result = STD.SAFE_JSON.parse(invokeRsp);

// 4. 错误判定（不同外部系统 code 不一样）
let isSuccess = (result.code === 200 || result.code === 0 || result.code === "0" || result.success === true);
if (!isSuccess) {
  throw "外部系统调用失败：" + (result.message || JSON.stringify(result));
}
```

**真实示例**：
- `SITF_AGENCY_TASK_EXP_INVOKE-26.js:59-71`（fetchToken + Bearer + doPost）
- `SITF_RCV_ASYNC_EXP.js:566-577`（CodeBlock 方式）
- `SITF_HMSG_MESSAGE_EXP_INVOKE-3.js:125-145`（飞书 app_access_token 模式）

**注意事项**：
- ⚠️ 多数 HTTP 调用无超时配置（默认很长）→ 风险见 T08
- ⚠️ `doPost` 返回字符串，需要 `SAFE_JSON.parse` 后再用
- ⚠️ 状态码判定要按外部系统约定：HTTP 200/业务 code 0/"0" 都可能是成功

## P06 · HTTP Basic Auth（OTHER.ITF_TOOL.base64Encode）

**适用场景**：旧式 ERP/OA 集成（SAP RFC / 用友 NC / 金蝶 K3）。

**代码模板**：
```javascript
// 1. 拼接 user:password
let basic = itfCtx.userName + ":" + itfCtx.password;
// 2. Base64 编码
let basicAuthorization = OTHER.ITF_TOOL.base64Encode(basic);
// 3. 拼 header
let httpHeaders = {
  Authorization: "Basic " + basicAuthorization
};
// 4. 调用
let invokeRsp = STD.HttpClient.doPost(url, httpHeaders, requestData);
```

**真实示例**：
- `SITF_PO_EXP_INVOKE-1.js:448-462`（中环领先 SAP）
- `SITF_GENERIC_POST_SCUX_COMMON7-11.js`（飞书 Basic Auth）
- `SITF_GENERIC_POST_SCUX_COMMON3-41.js`（通用 POST 模板）

**注意事项**：
- ⚠️ 凭据直接暴露在 Constants 配置中（已确认）：Bot 提示用户改用更安全的方案
- ⚠️ HTTP Basic 无加密传输；生产必须 HTTPS

## P09 · LOV 字典查询（queryIdpLov）

**适用场景**：value code → meaning 显示转换。

**代码模板**：
```javascript
// 1. 单个 lov 查所有
let lovList = STD.LovHelper.queryIdpLov("SSLM.HHHXCODE");
// lovList = [{value: "01", meaning: "类型A"}, {value: "02", meaning: "类型B"}]

// 2. 单条 code → meaning（懒查）
let meaning = STD.LovHelper.getIdpLovMeaning("SSLM.EXTERNAL_SUP_REQ_TYPE", reqTypeCode);

// 3. 批量 + 转 Map（脚本内 helper）
function queryLovMap(lovCodes, valueField) {
  let result = {};
  lovCodes.forEach(code => {
    let list = STD.LovHelper.queryIdpLov(code);
    if (!_.isEmpty(list)) {
      result[code] = {};
      list.forEach(lov => {
        result[code][lov.value] = valueField ? lov[valueField] : lov;
      });
    }
  });
  return result;
}
```

**真实示例**：
- `SINV_RCV_TRX_DATA_SUBMIT_AFTER-5.js:4, 20`
- `SSLM_EXTERNAL_SUPPLIER_APPROVE_AFTER.js:52`
- `SSRC_RFX_HEADER_QUERY_AFTER_HANDLE.js:82-99`（queryLov helper）

**注意事项**：
- ⚠️ `queryIdpLov` 返回整个 lov 列表（可能 100+ 项），适合离线缓存到 Map
- ⚠️ lov 缓存 30 分钟（平台自动）；脚本不要每条都查

## P15 · 数据转换 helper 函数集

**适用场景**：脚本内频繁使用；lovTranslate / 数据合并 / Map 转换。

**代码模板**：
```javascript
// === union：合并新旧数据（去重保留新值）===
function union(paramList, dbList, primaryKey) {
  let result = [];
  if (_.isEmpty(paramList)) {
    return dbList == null ? [] : dbList;
  }
  if (_.isEmpty(dbList)) {
    return paramList;
  }
  // 前端入参中可能存在新增和变更两种数据
  let idList = _.map(paramList.filter(e => e[primaryKey] != null), e => e[primaryKey]);
  // 筛选出 DB 有但前端没传的（即真正删除的）
  let dbFiltered = dbList.filter(e => idList.indexOf(e[primaryKey]) >= 0);
  result.push(...paramList, ...dbFiltered);
  return result;
}

// === lovTranslate：批量 value → meaning ===
function lovTranslate(source, target /* {"字段A": "LOV_CODE"} */) {
  let lovMap = queryLov(Object.values(target));
  let handle = (obj, field, lovCode) => {
    if (obj[field] == null) {
      obj[field + "Meaning"] = "";
      return;
    }
    let codes = obj[field].indexOf("[") > -1
      ? STD.SAFE_JSON.parse(obj[field])
      : obj[field].split(",");
    let meanings = codes.map(c => lovMap[lovCode][c]?.meaning || "").filter(Boolean);
    obj[field + "Meaning"] = meanings.join(",");
  };
  if (Array.isArray(source)) {
    source.forEach(obj => {
      for (let field in target) handle(obj, field, target[field]);
    });
  } else {
    for (let field in target) handle(source, field, target[field]);
  }
}

// === toMap：数组 → Map（key→value）===
function toMap(data, keyField, valueField) {
  if (_.isEmpty(data)) return {};
  if (valueField == null) {
    return data.collectors().toMap(x => x[keyField], x => x);
  }
  data = data.filter(e => e[keyField] != null);
  return data.collectors().toMap(x => x[keyField], x => x[valueField]);
}
```

**真实示例**：
- `SSRC_RFX_HEADER_QUERY_AFTER_HANDLE.js:59-77`（union）
- `SSRC_RFX_HEADER_QUERY_AFTER_HANDLE.js:104-162`（lovTranslate）
- `SINV_RCV_TRX_DATA_SUBMIT_AFTER-5.js:38-48`（Java-style collectors）
- `SSRC_RFX_HEADER_QUERY_AFTER_HANDLE.js:236-246`（toMap）

**注意事项**：
- ⚠️ `_.isEmpty()` 检查放在函数首句（lodash 全局可用，但 Bot 应明示 require）
- ⚠️ `.collectors()` 是 GraalVM 的 Java Stream API 暴露 — 见 T12 风险
- ⚠️ `_.find/_.filter/_.map/_.keys/_.sortBy` 都是 lodash 全局假设

**支持的 opr 值**：

| opr | 含义 | 示例 |
|-----|------|------|
| `=` | 等于 | `{opr: "=", v: "value"}`（默认） |
| `in` | IN | `{opr: "in", v: [...]}` |
| `not in` | NOT IN | `{opr: "not in", v: [...]}` |
| `is null` | IS NULL | `{opr: "is null"}` |
| `is not null` | IS NOT NULL | `{opr: "is not null"}` |
| `>`, `>=`, `<`, `<=` | 比较 | `{opr: ">=", v: "2025-01-01"}` |
| `like` | LIKE | `{opr: "like", v: "%xxx%"}` |

**注意事项**：
- ⚠️ 简单等值条件可省略 opr/v：`{field: value}`
- ⚠️ **日期比较用字符串**：v3 引擎自动转；不能用 JS Date 对象
- ⚠️ LIKE 必须包含通配符 `%xxx%`；不带通配符等价于 `=`
- ⚠️ 大 IN（>1000）会被 SQL 拦截；Bot 应自动拆批

## P22 · Bot 编写脚本的 6 大决策树

**适用场景**：用户需求 → Bot 选 API 时的决策路径。

```
1. 业务对象读写 → objectOperation (v3 ORM, 90%)
   ↓ 复杂批量 → STD.Database.batchInsert/batchUpdateOptional (v2 ORM)
2. 调用外部 HTTP 系统 → STD.HttpClient (90% 集成)
   ↓ 有客户封装 → STD.CodeBlock.execute("SITF_COMM_HTTP_TOOL")
   ↓ 跨服务 → feignClient.doGet/doPost

   ↓ 单条 → getIdpLovMeaning
4. 触发审批 → workFlow.start (processStartDTO)
5. MQ 异步 → STD.MarmotQueue.produce (内部) / OTHER.MQ (原始)
   ↓ 防重 → RelTable 幂等表 + status
6. 附件外发/下载 → attachment.fetchServiceFilesByUUID + getSignedUrl + uploadAttachmentByUrl
```
